# دستورالعمل کاربری حل‌گر (راهنمای اجرا)

این سند یک راهنمای کوتاه و کاربردی برای اجرای کد حل‌گر ترموالاستیسیته
لرد-شولمنِ استوانهٔ چندلایهٔ متخلخل تقویت‌شده با گرافن است. برای شرح فنیِ کاملِ
ساختار درونی کد به سند «شرح فنی حل‌گر» مراجعه شود.

## ۱. پیش‌نیازها

- **MATLAB R2026a** (یا نسخهٔ سازگار). هیچ جعبه‌ابزار خاصی لازم نیست؛ تنها
  توابع پایه‌ای و `ode15s` (برای صحت‌سنجی) استفاده می‌شوند.
- فایل اصلی حل‌گر: `LSTE_solver_R8.m` (آخرین/نهاییِ نسخه). نسخه‌های پیشین `LSTE_solver_R1.m`
  تا `LSTE_solver_R7.m` منجمد (frozen) هستند و برای بازتولید نتایج قدیمی و ردگیریِ تغییرات
  نگه داشته شده‌اند. نسخهٔ R8 از نظر فیزیک با R7 (و در نتیجه R6) رقم‌به‌رقم یکسان است؛
  تنها تفاوتِ آن این است که مقادیرِ پیش‌فرضِ پیکربندی به **حالتِ مرجعِ رساله** تنظیم
  شده‌اند (نسخهٔ R7 به یک هندسهٔ آزمونِ کوچک پیش‌فرض بود). نسخهٔ R7 اشیای صریحِ
  شماره‌دهی/نگاشتِ درجات آزادی (`NodeMap`,`DOFmap`,`GridDOF` + خروجی CSV) را افزوده بود
  (پاسخ به Prom.2 ص۴). توجه: کارزارِ فصل چهارم همچنان `LSTE_solver_R7` را فرا می‌خواند
  (فیزیک ≡ R8؛ همهٔ پیش‌فرض‌ها از راه `cfg` بازنویسی می‌شوند).
- مسیر اجرای متلب در این پروژه:
  `C:\Program Files\MATLAB\R2026a\bin\matlab.exe`.

## ۲. اجرای یک حالت منفرد (standalone)

ساده‌ترین راه، ویرایش بلوک پیکربندی در بالای `LSTE_solver_R8.m` و اجرای مستقیم آن است:

```matlab
% در پنجرهٔ فرمان متلب، در پوشهٔ claude\
LSTE_solver_R8
```

پارامترهای اصلی در بلوک «۰. Model configuration» و بخش‌های ۱ و ۲ قرار دارند.
مهم‌ترین‌ها:

| پارامتر | معنی | مقدار پیش‌فرض (R8 = حالتِ مرجعِ رساله) |
|---|---|---|
| `theory` | تئوری: `'FOURIER'`،`'LS'`،`'DPL'`،`'GN3'` | `'LS'` |
| `tau0` | زمان تخفیف τ₀ (s) | `418` |
| `coupling_on` | فعال‌بودن جملهٔ ممزوج | `true` |
| `BC_z` | تکیه‌گاه دو انتها: `'S'`،`'C'`،`'F'`،`'R'` | `'S'` |
| `BC_z0`,`BC_zL` | بازنویسی هر انتها جداگانه (خالی = `BC_z`) | `''` |
| `GPL_pattern` | الگوی گرافن: `'UD'`،`'O'`،`'X'`،`'V'`،`'A'` | `'UD'` |
| `porosity_pattern` | الگوی تخلخل | `'UD'` |
| `W_GPL_total` | کسر وزنی کل گرافن | `0.003` |
| `em3` | ضریب جرمی تخلخل (سطح تخلخل) | `0.8980` |
| `a_GPL,b_GPL,t_GPL` | نیم‌طول/نیم‌عرض/ضخامت پلاکت (m) | `2.5e-6,1.5e-6,1.5e-9` |
| `NL` | تعداد لایه | `7` |
| `R_i,R_o,L` | شعاع داخلی/خارجی/طول (m) | `1.0,1.5,2.1` |
| `N_r,N_z` | نقاط DQ شعاعی/محوری | `15,11` |
| `T_in_val` | دمای نهایی سطح داخلی (K) | `600` |
| `h_c` | ضریب همرفت سطح خارجی (W/m²K) | `10` |
| `P_i` | فشار داخلی (Pa) | `50e6` |
| `total_time`,`dt` | زمان کل/گام زمانی (s) | `3000,1` |
| `gam,bet` | پارامترهای نیومارک δ,β | `0.5,0.25` |

**توجه:** در نسخهٔ **R8** مقادیرِ پیش‌فرضِ ستونِ بالا همان **حالتِ مرجعِ رساله**‌اند
(استوانهٔ توخالیِ ضخیم با $R_i=1{,}0$ m، $R_o=1{,}5$ m، ضخامت جدار $h=0{,}5$ m، طول
$L=2{,}1$ m، $N_L=7$ لایه با فصل‌های مشترک در $\xi=k/7$، شبکهٔ قفل‌شدهٔ
$N_r=15$/$N_z=11$، بارگذاریِ ۳۰۰→۶۰۰ کلوین، $P_i=50$ مگاپاسکال، $\tau_0=418$ ثانیه،
$۳۰۰۰$ ثانیه با گام $۱$ ثانیه). بنابراین اجرای مستقیمِ `LSTE_solver_R8` همین حالتِ مرجع را
بازتولید می‌کند (برخلافِ R7 که به یک هندسهٔ آزمونِ کوچک پیش‌فرض بود). **تنها استثنا:**
ضریبِ تخلخلِ پیش‌فرضِ فایل ($em3=0{,}8980$) با مقدارِ به‌کاررفته در کارزار/فصل چهارم
($em3=0{,}8604$) یکی نیست، زیرا بخشِ تخلخل عمداً تا نهایی‌شدن بر پایهٔ فایل MZ (بند
A7) دست‌نخورده مانده است؛ پس اجرای مستقلِ R8 در هندسه و بارگذاری با حالتِ مرجع یکی است
اما در ضریبِ تخلخل باید `em3=0.8604` از راه `cfg` نشانده شود.

> **توجه (الگوهای تخلخل):** الگوهای تخلخل (UD/O/X/V/A) از روی فرمول‌های `MZ-R 0.docx`
> پیاده‌سازی شده‌اند و از نسخهٔ R3_1 به بعد **هیچ هشدارِ زمان‌اجرایی** برای آن‌ها صادر
> نمی‌شود (تنها هشدارِ باقی‌مانده مربوط به نامِ نامعتبرِ میدانِ `cfg` است). طبق بازخورد
> Prom.2 (بند ز / A7) نهایی‌سازیِ روابطِ تخلخل بر پایهٔ فایل MZ بر عهدهٔ نویسنده است و
> بلوکِ تخلخل تا آن زمان دست‌نخورده نگه داشته شده است.

## ۳. اجرای دسته‌ای با سازوکار `cfg` (بدون ویرایش فایل)

برای مطالعات پارامتری، فایل حل‌گر ویرایش **نمی‌شود**؛ به‌جای آن یک ساختار
`cfg` در فضای کاری ساخته می‌شود و حل‌گر مقادیر آن را پس از بلوک پیکربندی اعمال
می‌کند. حل‌گر در ابتدا `clearvars -except cfg` می‌کند، سپس هر میدان `cfg` را
با `eval` روی متغیر متناظر می‌نشاند. اگر نام میدانی با هیچ متغیر پیکربندی
مطابقت نداشته باشد، یک `warning` صادر می‌شود (محافظت در برابر غلط املایی).

```matlab
cfg = struct();
cfg.theory       = 'LS';
cfg.GPL_pattern  = 'V';
cfg.porosity_pattern = 'A';
cfg.W_GPL_total  = 0.04;
cfg.BC_z0 = 'S';  cfg.BC_zL = 'C';     % تکیه‌گاه ترکیبی
cfg.out_name = 'results\my_case.mat';
LSTE_solver_R8;                              % cfg به‌طور خودکار اعمال می‌شود
```

نکته: میدان‌ها را با «ادغام میدانی» (تخصیص جداگانه) بسازید، نه با
`struct('BC_z','S', ... )` که در صورت تکرار نام میدان خطا می‌دهد.

## ۴. اجرای کارزار پارامتری از PowerShell

اسکریپتِ اصلیِ کارزارِ فصل چهارم `campaign\run_ch4_campaign.ps1` (به‌همراهِ
`campaign\run_nz_sweep.ps1` برای جاروبِ $N_z$) هر حالت را با یک `cfg` جداگانه در یک
نمونهٔ `matlab -batch` اجرا می‌کند، نتایج را در پوشهٔ `param_studies_ch4\` می‌نویسد و
موجودها را رد می‌کند (skip-existing). این دو، ۸۶ حالتِ فصل چهارم را می‌سازند.
(اسکریپت‌های قدیمیِ `run_param_studies*.ps1` نسخهٔ ۱ تا ۶ برای هندسهٔ قدیمی بودند و به
پوشهٔ حذف‌شدهٔ `param_studies\` می‌نوشتند؛ اکنون در `campaign\_archive\` بایگانی شده‌اند.)

```powershell
# در پوشهٔ claude\
powershell -File .\campaign\run_ch4_campaign.ps1
powershell -File .\campaign\run_nz_sweep.ps1
```

> **محدودیت مهم:** بیشینهٔ **۳** نمونهٔ `matlab -batch` هم‌زمان مجاز است؛ نمونهٔ
> چهارم خطای گذرای مجوز MathWorks (کد ۵۰۰۱) ایجاد می‌کند. اجراهای شکل/آمار را
> هم‌زمان با کارزار به‌عنوان نمونهٔ چهارم اجرا نکنید.

## ۵. تولید شکل‌ها

پس از اتمام کارزار، اسکریپت‌های شکل، فایل‌های `.mat` را خوانده و مجموعه شکل‌های
سیاه‌وسفید و رنگی را می‌سازند:

```matlab
% خانوادهٔ کاتالوگِ فصل چهار — می‌خوانند از param_studies_ch4\ و می‌سازند در figures_ch4_bw\ و figures_ch4_color\
catalog_R6            % ۴-پنل: T*,U* بر حسب Fo و T*,Σθθ بر حسب ξ
catalog_R6_color      % همان، رنگی
catalog_R6_full       % ۸-پنلِ کاملِ کرنش/تنش
catalog_R6_extras     % پیشانی‌های صوتِ دوم + ماتریسِ ۵×۵ گرافن×تخلخل
catalog_gplpor        % شکل‌های به‌تفکیکِ تخلخل
catalog_bestworst     % بهترین/بدترین
catalog_conv, catalog_conv2   % همگرایی (هر دو سبک B&W و رنگی)
catalog_ch4_variants  % تکمیلِ نسخه‌های کم‌بودِ سیاه‌وسفید/رنگی
```

شکل‌های سیاه‌وسفید از رنگ‌های خاکستری + سبک خط + نشانگر استفاده می‌کنند تا در
چاپ تک‌رنگ خوانا باشند. شکل‌های گسترشی (T2/T3) با `T2_1_spatial_methods` و
اسکریپت‌های تئوری در `results_extensions\` تولید می‌شوند. (اسکریپت‌های قدیمیِ
`claude_param_figures*` برای هندسهٔ قدیمی بودند و در `code\_archive\` بایگانی شده‌اند.)

## ۶. خروجی‌ها

هر اجرا یک فایل `.mat` (نام از `out_name`) ذخیره می‌کند شامل:

- `tv` : بردار زمان.
- `hist_T`,`hist_U`,`hist_W` : تاریخچهٔ زمانی دما و جابجایی شعاعی/محوری نقطهٔ
  میانی ضخامت در مقطع میانی طول.
- `hist_Ti` : تاریخچهٔ دمای محرک سطح داخلی.
- `snaps`,`snap_t` : تصویرهای لحظه‌ای میدان کامل در چند زمان (برای پروفیل‌ها).
- در صورت `store_full_history=true`: `X_hist` (کل میدان در هر گام زمانی، ابعاد
  `Ndof × (Nt+1)`).
- **(افزودهٔ R7)** اشیای صریحِ شماره‌دهیِ درجات آزادی: `NodeMap` (ماتریس
  گرهیِ مستطیلیِ یک لایه با ابعاد `N_r × N_z`)، `DOFmap` (یک سطر برای هر درجهٔ
  آزادی، در ترتیب معادلات با بلوک‌های میدانیِ `[θ|u|w]`) و `GridDOF` (سه درجهٔ
  آزادیِ سراسری در هر نقطهٔ شبکه). این‌ها فیزیک را تغییر نمی‌دهند و صرفاً
  ترتیبِ مونتاژ را مستند می‌کنند.

افزون بر فایل `.mat`، حل‌گر ماتریس نگاشت را به‌صورت یک فایل جداگانهٔ
`<out_name>_DOFmap.csv` (با سرستون `gdof,component,comp_name,layer_e,ir,iz,localnode,r,z`)
نیز صادر می‌کند تا برای سند مستندسازیِ کد قابل ارجاع باشد.

اسکریپت `chapter_stats_ch4.m` (در `code\misc`) این فایل‌ها را از پوشهٔ
`param_studies_ch4\` می‌خواند و جدول آماری `chapter_stats.csv` (بیشینه/نهاییِ
کمیت‌های بی‌بعد هر حالت، با بی‌بعدسازیِ هندسهٔ جدید) را می‌سازد که مبنای اعداد فصل
چهارم است. (نسخهٔ قدیمیِ `claude_chapter_stats.m` پوشهٔ حذف‌شدهٔ `param_studies\` را
می‌خواند و بایگانی شده است.)

## ۷. نقشهٔ نسخه‌ها

| نسخه | افزوده |
|---|---|
| `LSTE_solver_R1` | حل‌گر پایهٔ تصحیح‌شده (منجمد، صحت‌سنجی‌شده) |
| `LSTE_solver_R2` | موتور `cfg`، ذخیرهٔ کامل تاریخچه، فشار سینوسی |
| `LSTE_solver_R3`/`R3_1` | گزینه‌های شرط مرزی، الگوهای تخلخل نهایی |
| `LSTE_solver_R4` | شوک حرارتی گاوسی |
| `LSTE_solver_R5` | انتخاب تئوری (FOURIER/LS/DPL/GN3) |
| `LSTE_solver_R6` | تکیه‌گاه هر انتها جداگانه + ابعاد گرافن قابل‌بازنویسی از `cfg` |
| `LSTE_solver_R7` | ماتریس صریحِ شماره‌دهی/نگاشتِ درجات آزادی (`NodeMap`+`DOFmap`+`GridDOF` + خروجی `DOFmap.csv`)؛ از نظر فیزیک رقم‌به‌رقم یکسان با R6 (Prom.2 ص۴) |
| `LSTE_solver_R8` | **نسخهٔ رسمیِ رساله**؛ مقادیرِ پیش‌فرض = حالتِ مرجعِ رساله (اجرای مستقل، حالتِ مرجع را بازتولید می‌کند)؛ از نظر فیزیک رقم‌به‌رقم یکسان با R7. توجه: کارزار همچنان `LSTE_solver_R7` را فرا می‌خواند (فیزیک ≡ R8) |
| `LSTE_solver_R9` | **نسخهٔ کارایی (اختیاری)** — تنها بخشِ مونتاژِ حلقهٔ داخلی (بخشِ ۴-۱) برداری‌سازی شده (نوشتن‌های تُنُکِ عددی تک‌به‌تک جایگزینِ نوشتن‌های برداری/`kron` شده‌اند)؛ هیچ فیزیکی تغییر نکرده و بخشِ شرایطِ مرزی/فصلِ‌مشترک عیناً از R8 کپی شده. حدود ۲٫۱ برابر سریع‌تر در مجموع (۲٫۵ برابر در مرحلهٔ مونتاژ) روی حالتِ مرجعِ کاملِ ۳۰۰۰‌گامی، با اجرای متوالیِ بدونِ رقابتِ منابع سنجیده شده. صحت‌سنجی‌شده: در برابرِ R8 در پنج پیکربندی و حالتِ مرجعِ کامل تا دقتِ خطای گردکردنِ اعشارِ مضاعف مطابقت دارد، و به‌طور مستقل در برابرِ محکِ ادبیاتیِ ملک‌زاده-حیدرپور نیز بازآزمایی شده. **R8 هنوز نسخهٔ رسمیِ رساله است**؛ R9 برای کسی که به اجرای سریع‌تر نیاز دارد در دسترس است.

هر نسخه، نتایج پیش‌فرض نسخهٔ قبل را رقم‌به‌رقم بازتولید می‌کند (پیش از استفاده
راستی‌آزمایی می‌شود). قاعدهٔ کار: کد صحت‌سنجی‌شده هرگز درجا ویرایش نمی‌شود؛
ویژگی جدید = یک نسخهٔ جدید با افزوده‌های جراحی و نشانه‌دار.
